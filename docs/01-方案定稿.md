## 1. 目标与范围

**做**：手机 QQ 远控家用电脑上的 opencode agent——发指令、看反馈、工作过程互动、权限审批；自带 Web Dashboard 作第二视角。

**不做**：系统级远控（用户另有远控软件）；多平台前端（保留兼容，v1 只用 QQ）；外网组网 / ntfy（v2 预留）。

## 2. 最终架构

```
┌─ 安卓手机（零代理） ──────────────────────────────────────┐
│  QQ app（与机器人单聊）                                    │
│   ├─ 聊天：下指令 / 看反馈 / 权限卡【允许/拒绝/允许所有】   │
│   └─ （备用）浏览器 → Web Dashboard :9820（同 WiFi）       │
└──────────── QQ 官方 WS 网关（出站，免公网 IP）──────────────┘
                            │
┌─ 家用电脑 · WSL2 Ubuntu-24.04 · Docker ───────────────────┐
│  cc-connect 容器（restart:always + 每日定时重启）         │
│   ├─ QQ 平台适配（WS 网关 + 键盘按钮 INTERACTION_CREATE） │
│   ├─ 每会话 FIFO 队列（上限5）+ 60s 去重 + allow_from 白名单│
│   ├─ ACP agent ── stdio(Agent Client Protocol) ──►        │
│   │        opencode acp（常驻进程，v1.18.26 锁版）        │
│   │        └─ session/request_permission ⇄ 审批卡往返     │
│   └─ [[projects]] 多项目注册表，每项目独立 work_dir       │
│  工作区：~/AgentRoot（WSL ext4 本地）                     │
│  LLM 认证：挂载宿主机 opencode 凭证复用                   │
└───────────────────────────────────────────────────────────┘
```

## 3. 共识清单（12 条，全部已确认）

1. **目标**：飞书远控本机 opencode（发指令 / 看反馈 / 过程互动 / 权限审批）
2. **网关**：cc-connect；v1 跑 WSL2 Docker，自写 Dockerfile + compose
3. **Agent 接线**：cc-connect **ACP agent** 挂 `opencode acp`，权限审批原生转发到飞书卡
4. **权限模型**：opencode 原生 permission 配置驱动——AgentRoot 内 allow、跨目录/危险操作 ask（→飞书卡）、显式 deny 清单；每项目留 yolo 开关并写文档
5. **工作区**：WSL 本地 `~/AgentRoot`；项目登记进 `[[projects]]`，每项目独立 work_di
6. **手机端**：QQ 机器人（cc-connect `qqbot`，个人开发者）；WS 网关长连接免公网 IP；`allow_from` 白名单只放本人；v1 纯 QQ（变更见第 0 节）
7. **前端**：cc-connect 自带 Web Dashboard（:9820）容器映射 + 管理鉴权，同 WiFi 访问
8. **会话/队列**：用 cc-connect 内置——每会话 FIFO（上限 5）、60s 去重、/new /list /switch、30min 空闲自动新会话；**禁用 /stop**（#1776 bug）
9. **多机演进（v2）**：每台机器 = 一个 QQ 机器人 + 一个容器，手机里像选联系人一样选机器
10. **LLM 认证**：复用本机 opencode 登录凭证，挂载进容器，零重配
11. **未来迁移**：换 agent（OpenAI 兼容 API 等）只动 cc-connect 后端配置，手机端零改动
12. **license**：cc-connect 个人使用 + 提 issue 催作者补 LICENSE 文件（README 自述 MIT）

## 5. 权限模型细则

- opencode 配置（全局 `~/.config/opencode/opencode.json` + 项目级）：
  - AgentRoot 内：读/写/跑命令 allow
  - `external_directory`：ask → ACP → 飞书卡【批准/拒绝】→ RespondPermission 回写
  - 危险命令 deny 清单（rm 类/安装类按需增删）
  - 环境变量 `OPENCODE_PERMISSION` 可内联覆盖
- **兜底阶梯**（M0 失败时逐级降级，降级需用户确认）：
  - **A（首选）**：ACP 原生审批卡
  - **B**：serve 包装器 ~100 行——SSE 收 `permission.asked` + `POST /session/:id/permissions/:id` 应答 + 飞书卡；cc-connect `POST /hook`（{session_key, prompt|exec}）可作入站应急通道
  - **C**：无审批——默认拒绝 + 按项目 yolo 开关 + 文档放行
- opencode 插件层还有 `permission.ask` 源码级钩子（未文档化）与 `session.idle` 事件（v2 做 ntfy 通知用）

## 6. 会话模型

- 每"飞书聊天 × 项目"一个会话；/new /list /switch /current；30 分钟空闲自动新会话（`reset_on_idle_mins` 可配）
- 同会话连发消息进 FIFO 队列（上限 5，满则回提示）；/compress 手动压缩 + token 阈值自动压缩
- skills / subagent 由 opencode 自身解析（放 `~/.config/opencode/plugins`、skills 目录即可）
- **禁用 /stop**（#1776 会误清会话）
