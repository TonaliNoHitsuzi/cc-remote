## 生死点结果

### ① session/new 模型列表（风险 opencode #31076）——PASS

- **未复现** "No models available"；session/new 正常返回 sessionId
- 模型经 `configOptions`（category=model）暴露而非 ACP 规范的 `modes`/`models` 字段：**23 个模型**（zhipuai coding-plan 全系 + deepseek + kimi + opencode zen），默认 `opencode/big-pickle`
- initialize 协商 protocolVersion=1；凭证复用零重配生效

### ② 跨目录 ask 触发——PASS

- 任务"读 /etc/hostname"→ agent 发起 tool_call（`cat /etc/hostname`）→ **`session/request_permission`**（server→client request）
- 权限载荷精确：`locations:[{path:"/etc"}]`、`rawInput.directories:["/etc"]`（external_directory 语义）
- 选项：`once`(allow_once) / `always`(allow_always) / `reject`(reject_once)

### ③ 审批往返（批准 + 拒绝双路径）——PASS

- **批准**：应答 `once` → agent 继续执行 → 输出主机名 → `session/prompt` response 带 `stopReason:"end_turn"`
- **拒绝**：应答 `reject` → tool_call_update `status:"failed"`（"The user rejected permission..."）→ 会话正常 end_turn，**不挂死**

## 实现细节备忘（给 M2/M4）

1. **`session/new` 强制要求 `mcpServers` 为数组**（不传报 -32602 Invalid params）——cc-connect 已适配（`agent/acp/session.go:212,232` 传 `[]any{}`），自写客户端必须带
2. **完成信号在 `session/prompt` 的 response**（`stopReason:end_turn`），不要只等 stop 通知
3. 权限应答格式：`{outcome:{outcome:"selected", optionId}}`，optionId 实际值 `once`/`always`/`reject`
4. `initialized` 通知 opencode 不识别（报 -32601，无害，别发）
5. opencode 还发 `agent_thought_chunk`（思考流）、`usage_update`（token/成本）——飞书侧展示可利用
